No-JS Web Lab

A research demo: modern HTML and CSS can now do things that used to need JavaScript. Every demo below runs with zero lines of JavaScript. View the page source to check.

Research question: Which common interactive UI patterns can be built today with only HTML and CSS, and how well are they supported across browsers?

1Popover + anchor positioning (top, bottom, left, right)

Replaces: tooltip/dropdown libraries and manual position maths.   ✅ Works in your browser❌ Anchor positioning not supported in your browser
Top popup
Bottom popup
Left popup
Right popup

Before: JavaScript

btn.onclick = () => {
  const r = btn.getBoundingClientRect();
  tip.style.top  = r.top - tip.offsetHeight - 8 + 'px';
  tip.style.left = r.left + r.width/2
                 - tip.offsetWidth/2 + 'px';
  tip.hidden = false;
};
document.onclick = e => { /* close if outside */ };
document.onkeydown = e => { /* close on Escape */ };

Now: HTML + CSS

<button popovertarget="t1"
  style="anchor-name:--b1">Top</button>
<div id="t1" popover>Top popup</div>

#t1 { position-anchor:--b1;
      position-area:top;
      inset:auto; margin:10px; }
/* outside-click + Esc closing is built in */

4Exclusive accordion with <details name>

Replaces: accordion scripts that close the other panels. name and ::details-content work in current Chrome, Firefox and Safari (per a May 2026 source). Smooth height animation needs interpolate-size, which is Chromium-only.   ✅ Smooth animation works here❌ Panels open instantly in your browser
What is the Popover API?
A built-in way to show a layer on top of the page, with light dismiss and focus handling.
What does the name attribute do?
Panels with the same name form a group. Opening one closes the others.
Is this accessible?
Yes. <details> is keyboard accessible and announced by screen readers. Exclusive groups have UX trade-offs, so use them thoughtfully.

Before: JavaScript

document.querySelectorAll('.panel-btn').forEach(b => {
  b.onclick = () => {
    document.querySelectorAll('.panel')
      .forEach(p => p.style.height = 0);
    b.nextElementSibling.style.height =
      b.nextElementSibling.scrollHeight + 'px';
  };
});

Now: HTML + CSS

<details name="faq">...</details>
<details name="faq">...</details>

:root { interpolate-size: allow-keywords; }
details::details-content { block-size:0;
  transition: block-size .3s,
              content-visibility .3s allow-discrete; }
details[open]::details-content { block-size:auto; }

7Scroll-driven animation

Replaces: scroll listeners and IntersectionObserver. The yellow bar at the top of this page and the fade-up of each section are pure CSS. Chrome/Edge 115+, Safari 26. Firefox: not enabled by default at the time of research.   ✅ Active in your browser❌ Not supported in your browser

Before: JavaScript

addEventListener('scroll', () => {
  const p = scrollY /
    (document.body.scrollHeight - innerHeight);
  bar.style.transform = `scaleX(${p})`;
});

Now: CSS

.progress { transform-origin:left;
  animation: grow linear both;
  animation-timeline: scroll(root); }
@keyframes grow {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); } }

9Enter and exit animations with @starting-style

Replaces: setTimeout / transitionend juggling before removing an element. Baseline (newly available) since 2024.   ✅ Works in your browser❌ Not supported in your browser
✅ Saved! This slid in with CSS only. Click outside to dismiss.

Before: JavaScript

el.classList.add('show');
/* to hide: */
el.classList.remove('show');
el.addEventListener('transitionend', () => {
  el.hidden = true;
}, { once: true });

Now: CSS

#toast { transition: opacity .35s, translate .35s,
  display .35s allow-discrete,
  overlay .35s allow-discrete; opacity:0; }
#toast:popover-open { opacity:1; }
@starting-style { #toast:popover-open { opacity:0; } }
